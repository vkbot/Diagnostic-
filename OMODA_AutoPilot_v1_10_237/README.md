# OMODA AutoPilot 1.3

Android 11 (API 30), ARM64, головное устройство OMODA/CHERY.
Package: `com.github.uiautomator`. Приложение по умолчанию: `com.github.uiautomator.test`.

## Как пользоваться

1. Открыть приложение и нажать **ЗАПУСТИТЬ**. Приложение само включит Wi-Fi, дождётся сети и запустит приложения из списка.
2. Автозапуск при загрузке работает сам, отдельных действий не нужно.
3. В **Настройках** можно выключить Wi-Fi или запуск при загрузке, поменять задержку и список приложений.

## Флаг «уже запускалось»

- После любого запуска (автоматического или кнопкой) приложение запоминает текущее включение ГУ.
- Повторный автоматический запуск в этом же включении пропускается.
- При перезагрузке флаг сбрасывается сам: сохраняется `boot_id` ядра Linux, и после перезагрузки он меняется.
- Кнопка **ЗАПУСТИТЬ** работает всегда, флаг её не блокирует.

## Сборка и подпись

1. `.\gradlew.bat assembleRelease` из корня проекта.
2. `scripts/sign_platform.sh <unsigned.apk> <platform.pk8> <platform_x509.pem> <out.apk>` с ключами вне проекта.
3. Проверить сертификат через `apksigner verify --print-certs`: SHA-256 должен совпасть с отпечатком платформы.

## Ограничения, которые проверить на ГУ

1. Фоновый запуск Activity из сервиса на Android 10+ может блокироваться прошивкой. Тогда нужна кнопка в уведомлении.
2. Подтверждение запуска best-effort: UNCONFIRMED означает «проверьте экран».
3. `setWifiEnabled()` работает при targetSdk 28, но OEM может запретить.
4. Проверить, что на ГУ нет другого пакета `com.github.uiautomator`: `adb shell pm list packages | grep uiautomator`.
5. Перед установкой удалить версии 1.0 и 1.1 (`ru.omoda.autopilot`).

Логи: `adb logcat -s OMODA-AutoPilot`.
